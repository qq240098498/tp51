# tp51 接口调试与用例回归对比平台

一个本地小工具：在页面上填好请求方式、目标地址、请求头与请求内容，点发送就把请求真的发出去，结果区显示响应状态、耗时、响应头与响应内容，失败时显示失败原因；常用的请求可以存成用例，之后一键回填再发一遍。页面上还能维护多套环境与环境变量，请求区里写成 `{{变量名}}` 的地方会按当前生效环境实时替换，发出去的是替换后的实际内容。

服务端内置了几个示例接口，本机不填任何外部地址也能直接试出完整效果。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件直接由后端静态目录提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5051>

端口固定为 `5051`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 在右侧环境管理区新增环境（默认已带开发、测试、生产三套），通过下拉切换当前生效环境，并为环境逐条添加变量
2. 请求区填好请求方式与目标地址，需要时再补请求头与请求内容，这三处都可以写成 `{{变量名}}` 引用当前环境的变量
3. 请求区下方的实际内容预览会随输入实时更新，带绿色底色的片段表示该处由变量替换而来，顶部还列出每个变量被换成了什么值
4. 点发送请求时会先做替换与校验：变量未定义、变量名为空、占位没闭合，或替换后目标地址不成立、JSON 内容不合法，都会在请求区指出是哪一处、哪个变量，这一次发送不会发出去
5. 校验通过后真正发出去的是替换后的实际内容，结果区出现状态码、耗时、内容大小、响应头与响应内容；内容能解析成结构化数据时按层级铺开显示，也可以切到原始文本
6. 目标地址填成不通的地址时，结果区给出失败原因，例如找不到主机、端口拒绝连接、等待超过上限
7. 想要留着下次再用，就填上用例名称点保存为用例，保存下来的是带 `{{变量名}}` 的模板原文，切换环境后回填即可得到不同取值
8. 用例列表里点回填，用例保存下来的内容会写回请求区，可以直接点发送请求重发；点详情看完整内容，点删除会先确认

目标地址有两种写法：以 `/` 开头表示本机内置示例接口，例如 `/demo/echo`；也可以填写 `http://` 或 `https://` 开头的完整地址。请求头留空的行会被忽略，同名请求头重复填写会被拒绝并指出是第几行。

### 多环境与变量

- 环境管理支持新增、重命名、切换当前生效环境与删除环境；删除当前环境后会自动切到剩余的第一个环境
- 每个环境下可以逐条添加变量，变量名与取值都填在页面上，列表按添加顺序展示当前环境的全部变量与取值（取值可直接在列表里修改，失焦自动保存）
- 变量名为空、变量名含非法字符（只允许字母、数字、下划线、中划线与点）或同一环境下变量重名时，会当场拒绝并指出是第几条不成立
- 删除变量时，如果同名变量仍被其他环境引用，不会静默删除：页面先给出结论、列出引用它的环境，确认后才只删除当前环境这一条，其他环境里的同名变量保持不变；删除完成后也会再明确说明其他环境仍然保留
- 目标地址、请求头名称与取值、请求内容都支持 `{{变量名}}` 写法；变量名比对忽略大小写（`{{Host}}` 能取到 `host` 的值）
- 保存用例只校验占位语法（变量在当前环境未定义也允许保存，因为可能在其他环境中定义）；实际发送前必须完成全部替换且替换结果成立

## 内置示例接口

| 名称     | 请求方式 | 路径                        | 说明                                                                 |
| -------- | -------- | --------------------------- | -------------------------------------------------------------------- |
| 回声接口 | 任意     | `/demo/echo`                | 把收到的请求方式、请求头、查询参数与请求内容原样回显                 |
| 报错接口 | 任意     | `/demo/status?code=500`     | 按地址里的取值返回对应状态码，取值需要在 200 到 599 之间             |
| 列表接口 | GET      | `/demo/items?page=1&size=3` | 返回带分页信息的条目列表，每页条数最多 20 条                         |
| 延迟接口 | 任意     | `/demo/slow?ms=1500`        | 等待指定毫秒数之后再返回，取值需要在 0 到 10000 之间                 |

页面的请求区里列出了这四个接口，点填入请求区就会把示例内容写好，直接点发送请求即可。示例调用也可以在地址上带参数：回声接口带查询参数会一并回显，报错接口把 `code` 改成 404 或 500 能看到不同的失败状态，列表接口把 `page` 与 `size` 调大能看到更长的列表，延迟接口把 `ms` 调到 3000 能看到更明显的等待反馈。

## 当前已具备的能力

- 多环境管理：新增与重命名环境、切换当前生效环境、删除不再使用的环境（删当前环境自动切换）
- 环境变量：每个环境逐条添加变量，页面列表展示当前环境全部变量，取值可在列表里直接修改并自动保存
- 变量校验：变量名为空、名字含非法字符或同环境重名当场拒绝，并指出是第几条不成立
- 删除引用保护：删除仍被其他环境引用的变量时先返回结论、列出引用环境，确认后才只删当前环境这一条，不静默删除
- 变量引用方式：目标地址、请求头名称与取值、请求内容都可写成 `{{变量名}}`
- 实时预览：选好当前环境后，页面随时展示替换后的实际内容，替换段以绿色底色标出，顶部附变量→取值对照表
- 发送拦截：变量未定义、变量名为空、占位未闭合，或替换后地址不成立、JSON 不合法时，指出具体位置与变量名，本次不允许发送
- 模板化用例：用例保存的是带占位的模板原文，占位语法问题当场拒绝；切换环境回填同一用例可得不同实际内容
- 请求区填写草稿：请求方式、目标地址、请求头（可增行、可删行）、请求内容、用例名称
- 真正发送请求：由服务端代发并再做一次占位残留兜底，本机示例接口与外部完整地址都支持
- 结果区展示：响应状态与状态说明、耗时、内容大小、目标地址、响应头逐行展示、响应内容按结构或原始文本查看
- 失败反馈：网络层失败给出可读原因与详细信息，请求内容与请求方式不匹配、目标地址格式不对等问题会标到对应输入项上
- 发送等待反馈：等待期间结果区显示等待提示，发送按钮显示发送中
- 保存用例：保存前校验目标地址占位语法、请求头字面量合法性与重复情况、请求内容占位语法，出错时页面会指出是哪一项的问题
- 用例列表：展示全部用例，标记出保存时写的是本机示例接口地址的条目，可按创建时间从新到旧排列，支持手动刷新
- 回填用例：把用例保存下来的请求方式、目标地址、请求头与请求内容写回请求区，可直接重发
- 查看用例：在详情区展示该用例保存下来的地址、请求头、请求内容与保存时间，详情区也能直接回填
- 删除用例：删除前先确认，删除后列表与详情同步更新

## 数据存储

所有数据写在 `data/db.json`，顶层结构为 `{ "activeEnvironmentId": "...", "environments": [...], "cases": [...] }`。每个环境包含 `id`、`name`、`variables: [{ key, value }]`、创建与更新时间。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。旧版本只含 `cases` 的数据文件在首次读取时会自动补入三套示例环境，已有的用例原样保留。

## 接口一览

| 方法   | 路径                                       | 说明                                             |
| ------ | ------------------------------------------ | ------------------------------------------------ |
| GET    | /api/health                                | 服务状态检查                                     |
| GET    | /api/demos                                 | 内置示例接口清单                                 |
| POST   | /api/send                                  | 按替换后的实际草稿发送一次请求（残留占位会拒绝） |
| GET    | /api/cases                                 | 获取用例列表                                     |
| GET    | /api/cases/:id                             | 获取单条用例                                     |
| POST   | /api/cases                                 | 保存一条用例（允许 `{{}}` 模板）                 |
| DELETE | /api/cases/:id                             | 删除一条用例                                     |
| GET    | /api/environments                          | 获取环境列表与当前生效环境                       |
| POST   | /api/environments                          | 新增环境                                         |
| PATCH  | /api/environments/:id                      | 重命名环境                                       |
| POST   | /api/environments/:id/activate             | 切换当前生效环境                                 |
| DELETE | /api/environments/:id                      | 删除环境                                         |
| POST   | /api/environments/:id/variables            | 向环境添加一条变量                               |
| PUT    | /api/environments/:id/variables/:key       | 修改变量取值                                     |
| DELETE | /api/environments/:id/variables/:key       | 删除一条变量；仍被其他环境引用时返回 409 与清单  |

删除变量的 409 响应里，`error.details.referencedBy` 给出仍引用同名变量的环境清单；页面给出结论后以 `?force=true` 重新请求表示用户已知情、只删当前环境这一条。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。发送接口的返回值里带上发送是否完成、状态码、耗时、响应头与响应内容，目标不可达时同样以正常返回值描述失败原因，页面按失败外观展示。
