# tp51 接口调试与用例回归对比平台

一个本地小工具：在页面上填好请求方式、目标地址、请求头与请求内容，点发送就把请求真的发出去，结果区显示响应状态、耗时、响应头与响应内容，失败时显示失败原因；常用的请求可以存成用例，之后一键回填再发一遍。

支持多环境与变量：可以维护多套环境，每套环境下逐条添加变量；请求区的目标地址、请求头与请求内容都能写成 `{{变量名}}` 引用当前环境的变量，页面上实时给出替换后的实际内容预览。变量缺失或替换后内容不成立时，这一次发送会被拦下并指出具体位置。

服务端内置了几个示例接口，本机不填任何外部地址也能直接试出完整效果。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件直接由后端静态目录提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5051>

端口固定为 `5051`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 请求区填好请求方式与目标地址，需要时再补请求头与请求内容
2. 点发送请求，结果区出现状态码、耗时、内容大小、响应头与响应内容；内容能解析成结构化数据时按层级铺开显示，也可以切到原始文本
3. 目标地址填成不通的地址时，结果区给出失败原因，例如找不到主机、端口拒绝连接、等待超过上限
4. 想要留着下次再用，就填上用例名称点保存为用例
5. 用例列表里点回填，用例保存下来的内容会写回请求区，可以直接点发送请求重发；点详情看完整内容，点删除会先确认

目标地址有两种写法：以 `/` 开头表示本机内置示例接口，例如 `/demo/echo`；也可以填写 `http://` 或 `https://` 开头的完整地址。请求头留空的行会被忽略，同名请求头重复填写会被拒绝并指出是第几行。

## 多环境与变量

1. 右列「环境管理」里可以新增环境、重命名、删除，并用下拉框切换当前生效的环境；至少保留一个环境
2. 选中某个环境后，在下方逐条添加变量，变量名与取值都直接填在页面上，列表里能看到当前环境的全部变量；输入停顿后自动保存
3. 变量名为空、名字不合法（需以字母或下划线开头，只能含字母、数字、下划线与中划线）、或同一环境下重名，都会当场拒绝并指出是第几条，修正前不保存、也不参与替换
4. 删除变量时会先给出明确结论：其他环境是否仍有同名变量、当前请求区的哪些位置还在引用它，确认后才删除
5. 请求区的目标地址、请求头（名称与取值）、请求内容都可以写成 `{{变量名}}`
6. 选好当前环境后，「实际内容预览」实时显示替换之后真正会发出去的内容，高亮段标出每一处 `{{变量名}}` 换成了什么值（空值会特别标出）
7. 变量未定义、变量名为空、或替换之后的地址/请求头/请求内容不成立（例如声明为 JSON 却解析不过）时，预览与请求区会指出是哪一处、哪个变量，这一次发送不允许发出去
8. 保存用例时保存的是带 `{{变量名}}` 的模板原文，之后回填发送时再按当时生效的环境替换，同一条用例在不同环境下可以直接复用

变量的作用域是单个环境：不同环境可以定义同名变量的不同取值（例如开发环境 `host=127.0.0.1:5051`、生产环境 `host=api.example.com`），切换环境后预览与发送取值立即变化。

## 内置示例接口

| 名称     | 请求方式 | 路径                        | 说明                                                                 |
| -------- | -------- | --------------------------- | -------------------------------------------------------------------- |
| 回声接口 | 任意     | `/demo/echo`                | 把收到的请求方式、请求头、查询参数与请求内容原样回显                 |
| 报错接口 | 任意     | `/demo/status?code=500`     | 按地址里的取值返回对应状态码，取值需要在 200 到 599 之间             |
| 列表接口 | GET      | `/demo/items?page=1&size=3` | 返回带分页信息的条目列表，每页条数最多 20 条                         |
| 延迟接口 | 任意     | `/demo/slow?ms=1500`        | 等待指定毫秒数之后再返回，取值需要在 0 到 10000 之间                 |

页面的请求区里列出了这四个接口，点填入请求区就会把示例内容写好，直接点发送请求即可。示例调用也可以在地址上带参数：回声接口带查询参数会一并回显，报错接口把 `code` 改成 404 或 500 能看到不同的失败状态，列表接口把 `page` 与 `size` 调大能看到更长的列表，延迟接口把 `ms` 调到 3000 能看到更明显的等待反馈。

## 当前已具备的能力

- 请求区填写草稿：请求方式、目标地址、请求头（可增行、可删行）、请求内容、用例名称
- 真正发送请求：由服务端代发，本机示例接口与外部完整地址都支持
- 结果区展示：响应状态与状态说明、耗时、内容大小、目标地址、响应头逐行展示、响应内容按结构或原始文本查看
- 失败反馈：网络层失败给出可读原因与详细信息，请求内容与请求方式不匹配、目标地址格式不对等问题会标到对应输入项上
- 发送等待反馈：等待期间结果区显示等待提示，发送按钮显示发送中
- 保存用例：保存前校验请求方式取值、目标地址格式、请求头名称与重复情况、请求内容是否为合法 JSON，出错时页面会指出是哪一项的问题
- 用例列表：展示全部用例，标记出保存时写的是本机示例接口地址的条目，可按创建时间从新到旧排列，支持手动刷新
- 回填用例：把用例保存下来的请求方式、目标地址、请求头与请求内容写回请求区，可直接重发
- 查看用例：在详情区展示该用例保存下来的地址、请求头、请求内容与保存时间，详情区也能直接回填
- 删除用例：删除前先确认，删除后列表与详情同步更新
- 多环境管理：新增、重命名、删除环境，切换当前生效环境，至少保留一个
- 环境变量：每个环境下逐条维护变量名与取值，空名、非法名、重名当场指出第几条，删除变量前说明其他环境与请求区的引用情况
- 变量引用：目标地址、请求头名称与取值、请求内容都支持 `{{变量名}}`
- 实际内容预览：随输入与环境切换实时刷新，高亮标出每一处替换及其取值，空值单独提示
- 发送拦截：变量未定义、变量名为空、替换后的地址/请求头/请求内容不成立时，定位到具体位置（可精确到某一行请求头）并阻止发送
- 模板化用例：用例保存模板原文，回填后按当前环境替换发送

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "cases": [...], "activeEnvironmentId": "...", "environments": [{ "id", "name", "variables": [{ "key", "value" }] }] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。老版本数据里没有环境集合时，首次读取会自动补齐开发/生产两套初始环境并回写，已有用例保持不动。

## 接口一览

| 方法   | 路径                          | 说明                                   |
| ------ | ----------------------------- | -------------------------------------- |
| GET    | /api/health                   | 服务状态检查                           |
| GET    | /api/demos                    | 内置示例接口清单                       |
| POST   | /api/send                     | 按当前环境替换变量后发送一次请求       |
| GET    | /api/cases                    | 获取用例列表                           |
| GET    | /api/cases/:id                | 获取单条用例                           |
| POST   | /api/cases                    | 保存一条用例（模板原文）               |
| DELETE | /api/cases/:id                | 删除一条用例                           |
| GET    | /api/environments             | 获取环境列表与当前生效环境             |
| POST   | /api/environments             | 新增环境并自动切换为生效环境           |
| PATCH  | /api/environments/:id/name    | 重命名环境                             |
| DELETE | /api/environments/:id         | 删除环境（生效中则自动落到第一个）     |
| PUT    | /api/environments/:id/active  | 切换当前生效环境                       |
| PUT    | /api/environments/:id/variables | 校验并全量保存某环境的变量列表       |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。发送接口的返回值里带上发送是否完成、状态码、耗时、响应头与响应内容，目标不可达时同样以正常返回值描述失败原因，页面按失败外观展示。
